# `scripts/inspect_model.py`

## Purpose

A diagnostic that answers "what is in this model file?" — point count, column names,
file size, and the SH share of bytes. It is the first command run against any new
checkpoint, and it produced the dissertation's motivating statistic: **SH is 77.4% of
the model file**.

## Line-by-line

### Lines 1–9 — Header and imports

```python
"""Print structure of a 3DGS PLY: point count, fields, SH degree, byte breakdown."""
import argparse
import os
import sys

sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "src"))

from sh_compression.ply_io import read_gaussian_ply
from sh_compression.storage import baseline_sh_bytes
```

Line 6 is a pattern repeated in every script: prepend `../src` to the module search
path, computed relative to *this file's* location rather than the working directory.
That means scripts work when invoked from anywhere — including from the Colab
notebook, which runs from the repository root — without requiring `pip install -e .`
first. Imports on lines 8–9 must come after it, which is why the file is not in
strict PEP 8 import order.

### Lines 12–25 — `main`

```python
def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--ply", required=True)
    args = ap.parse_args()
    m = read_gaussian_ply(args.ply)
    n = m.num_points
```

A single required argument. Note `read_gaussian_ply` performs the SH degree
validation described in [ply_io.md](ply_io.md), so pointing this at a degree-2 model
produces a clear rejection rather than misleading output — the inspection tool
doubles as a compatibility check.

```python
    print(f"file: {args.ply}")
    print(f"file bytes: {os.path.getsize(args.ply):,}")
    print(f"points: {n:,}")
    print(f"fields ({len(m.field_names)}): {m.field_names}")
    print(f"SH bytes (N*48*4): {baseline_sh_bytes(n):,} "
          f"({baseline_sh_bytes(n)/os.path.getsize(args.ply):.1%} of file)")
```

The report. `{:,}` inserts thousands separators, which matters when eyeballing
nine-digit byte counts. `{:.1%}` formats a fraction as a percentage.

**The last line is the one that mattered to the project.** It divides computed SH
bytes by measured file bytes, producing the 77.4% figure that motivates the entire
dissertation: if SH is over three-quarters of the file, it is the only compression
target worth pursuing.

Printing the full `field_names` list is what allowed the SH layout to be confirmed
against a real checkpoint — the output shows `f_dc_0..2` and `f_rest_0..44` in the
order the file stores them, corroborating the layout read from the upstream source.

### Lines 28–29 — Entry point


Standard guard, so the module can also be imported without executing.

## Why it matters

Two contributions beyond convenience:

1. **The motivating statistic.** "SH is 77.4% of the file" appears in the abstract,
   the background section, and the motivation — and it is generated by this script
   rather than quoted from a paper.

2. **A cheap compatibility gate.** Because it exercises the full PLY reader, running
   it against a new checkpoint validates the SH degree, the field set, and column
   length consistency before any expensive GPU work begins.
